# TEMU 完全同款助手

当前版本 **0.4.4，本机后台识别版**。按2026-10-19用户要求，从纯浏览器改为本机后台以优化主体核对；安装一次后随Windows登录自动启动。同事无需另装Node或Python。

由Codex和Qoder共同维护，[GitHub私有仓库](https://github.com/cyw-one14/temu-exact-match)。维护先读AGENTS.md、VALIDATION.md并检查git status，保留其他维护者改动。

## 安装与使用

1. 完整解压 dist/temu-exact-match-0.4.4-windows-x64.zip，双击 Install-TEMU.cmd。
2. 等待安装完成，在自动打开的本机助手页点击“复制扩展目录”。固定安装位置为当前用户 %LOCALAPPDATA%\TemuExactMatch。
3. Chrome/Edge扩展管理页开启“开发者模式”，加载刚复制的extension目录，并固定插件。
4. 刷新TEMU首页、列表或详情页，点击商品图片右上角“查同款”。需要第三方登录/验证时点“查看图搜页”。

适用64位Windows10/11。包内含全部模型、Node、Python及图像库；若缺微软Visual C++运行库，首次安装会从微软官方固定地址下载并展示交互安装窗口，可能需要管理员权限。正常识别只在本机计算，不配置云密钥。联网用于商品/第三方图搜及官方图片，各人仍需正常使用第三方账号与权限。

以后登录Windows自动隐藏启动43187后台，关闭侧栏不关闭服务。关闭侧栏会取消其HTTP请求，已经进入的单次模型/Python计算需要结束才能释放；再打开复用模型并继续尚未处理的候选。关机、休眠和退出登录期间不会继续核对。后台意外退出、持续无响应或模块异常会尝试自动恢复；插件会在60秒窗口内重新连接并重试当前请求。桌面“启动TEMU同款助手”图标用于备用启动，不需要输入命令。手动停止会关闭整个后台与恢复进程，避免自动重启抵消用户停止。详见[安装说明.md](安装说明.md)。

每次最多**50条去重候选**，所有来源共用上限，不足按实际数量；不代表全站或全站销量前50。保留后台图搜、显眼进度、人工双向调整及长期记忆、缩略图放大、列表收起、逐卡销量和原词、Top10与真实来源。候选不会直接当成同款。

原生ONNX Runtime默认使用最多4个CPU线程；启动预热模型、常驻OpenCV、下载/初筛重叠、同地址下载去重、原图证据及特征缓存复用。保留原模型系列及判断门槛，主体流程仍逐项执行。**50条全部10秒尚未验证达成**；用户指定牙膏挤压器607388216216240，已同意先交付后台和安装包，真实50条测速待恢复可读取的图搜结果后进行。单张探测不能当作50条成绩。

0.4.3在图搜页面加载期间提前准备所选参考图，减少采集结束后的首次等待；相同标准化图片的DINOv2中间特征在普通/人体关注核对间复用，避免重复推理。预处理不计为已核对商品，不改变判断门槛；取消、换图或关闭侧栏会终止等待及后续准备。新候选图片仍需逐张分割，首次查找速度受电脑CPU、图片和网络影响。

同时修复正常核对时后台被误重启的问题：耗时模型计算移到独立线程，计算期间健康检查和取消请求仍能响应。真正的计算线程退出或超时仍会触发后台恢复，相关商品保留未完成。

原扩展更新前先导出本次JSON。开发电脑继续加载 D:\00 Work\temu-exact-match\extension，重新加载并刷新TEMU即可；后台由维护者直接更新启动。新同事固定目录再次运行新版安装程序即可升级，不用卸载扩展。扩展公钥ID稳定；长期人工记忆仍保存在各浏览器storage.local，卸载/清除数据会丢失。更换加载目录的旧用户应先联系维护者迁移，保留原目录。

运行架构与安全边界见[NATIVE-RUNTIME.md](NATIVE-RUNTIME.md)。BROWSER-RUNTIME.md与LEGACY-SERVICE.md保留历史方案，当前交付以本文为准。轻量 temu-exact-match-extension.zip 需要配套后台，发同事请用完整Windows包。

## 同款判断规则

- 同图证据、SIFT快速核验或主体模型确认一致后保留同款；只有图像证据显示商品主体不同才排除。背景、排版、图片说明文字不属于商品主体。另有用户明确要求的颜色与轮廓补充规则，结果分别标注，不冒充细节已核验。
- 自0.2.14起先按标题相似/不相似分组，两组全部核对主体。主体一致即同款；仅标题相似组在主体核对完成且未匹配后，允许主体关注区域颜色相近归为同款，并注明颜色补充依据。品牌不单独放行。
- **新增轮廓补充**：上述流程后仍无法确认的候选，两个标题组及缺标题均比较主体外轮廓。沿用已抓取图片与原前景分割，通过人体关注掩码限制比较区域，不改原图或删除手；分割无效、人体与商品不能可靠区分或比对失败时保持无法确认。按较大前景连通区域比较，可核对多件图中完整的一件；连成一片、遮挡或分割错误仍可能影响结果，不从区域数推断套装数量。
- 轮廓按重心与等比例尺度对齐，保留凹陷结构，支持镜像与0–359度旋转搜索（先5度步进再局部1度细化）。在96像素网格中，交并比至少0.90且双向边界覆盖至少0.90（边界容差2像素）才归为outline-match“主体轮廓补充同款”。不要求标题、颜色、品牌或数量相同；明确已排除的主体差异不由此翻转，已有同款不重复核对。两项90%是工程门槛，不是同款概率或准确率；不同实物也可能有相近轮廓，这条放宽规则可能增加误判。
- 轮廓补充结果保留指标、对齐方向、主体区域和规则版本，卡片与销量/关键词区明确标注。可参与同口径销量Top10及真实原词来源统计；价格、标题、链接仍沿用抓取值。更新到title-groups-outline-v16后，旧会话自动重新核对，导出含outlineMatch依据。
- 同一种商品的单件 / 多件装链接都参与主体同款比较，原始标题、价格和链接分别保留，售卖数量差异单独注明；SKU 未绑定时不自动换算单件价。
- 先对已抓取标题分组、排序，再走原页面同图路径。后续两组候选都运行SIFT、完整实例与原BiRefNet-lite + DINOv2，包括镜像/旋转及人体关注；完成后仅标题相似组可检查主体颜色。标题不相似或缺失均不跳过主体核对，不生成商品价格、原标题或推荐关键词。
- 图片主体明确不同的证据保留；照片模糊、遮挡、缺少关键细节且未通过补充规则时保留待核对。轮廓指标由实际主体掩码计算，不由模型生成；文字规格检查不能否决图像同款。
- 原商品信息仅从已打开页面读取；原始图片和对应商品已有相册最多 3 张用于核对，不打开原商品或候选详情页。新选图会清空旧查询；旧判断会在匹配策略更新后重新自动核对。

## 进度显示、人工调整与长期记忆（0.2.15起）

0.4.4最多同时核对3条商品，侧栏显示已完成和正在处理的数量；参考图特征共享，返回顺序不影响商品归属或人工分类。后台仍随Windows登录启动并在意外中断后恢复。三路并行受CPU与内存限制，不能保证50条在1分钟内完成；历史图片的局部测速也不代表真实50条查询。

侧栏顶部显示醒目的进度卡片，核对进行时固定在可见顶部。四步为“收集商品 → 图片初筛 → 核对主体 → 查看结果”，同时显示当前商品、完成条数与分类数量。收集时百分比表示已用50条额度；暂停采集后，核对进度按本次实际候选条数计算。请求完成后才计数，暂停、本机识别错误和无法确认会明确提示；100%表示本轮候选已处理完（含人工归类、无法确认或失败记录），不表示全部都是同款、全站覆盖或识别准确率。主体阶段包含适用的颜色与轮廓补充；没有模型内部实时子步骤或预计剩余时间。

- 在同款卡片点“移出同款”，商品进入“非同款”页签；切换该页签，在误排除的卡片上点“归为同款”即可移回。
- “未确定”页签也可点“归为同款”或“标为非同款”。没有显示的候选可在该页签点“展开全部”。
- 人工调整显示独立标记，立即更新同款数、同口径销量Top10与逐链接关键词；原价、原标题、链接和词证据保留。自动依据收在“查看核对依据 / 查看差异”中，不改写成模型已确认。
- **0.2.16长期记忆**：人工决定保存在当前浏览器扩展本地存储，不自动过期。关闭浏览器、重启电脑、重新选图发起新分析后，同一参考商品+同来源候选链接再次出现会自动沿用，卡片显示“已记住你的分类”。重新自动核对、价格/原标题同步、在途核对响应不覆盖人工决定。
- 参考商品有ID时按ID记忆，换主图或原标题仍适用；没有ID的上传图片按文件原始字节SHA-256精确记忆，网页图则按原官方图片地址摘要精确记忆。修改/重编码文件或更换无ID图片地址可能不命中；不会根据标题或近似外观把历史调整套到其他参考商品。候选按数据来源+商品ID分开，TEMU与第三方来源的同ID条目不连带调整。无法可靠绑定的条目只在本次保留并提示。
- 点“恢复自动判断”同时撤销当前调整和该条长期覆盖，下次继续用自动结果；已取消的记录不会被旧会话重新迁入。旧版人工决定仅在原会话数据仍可读取时按缺失项迁移，迁移失败会提示。**升级前先导出当前分析JSON留档**：旧版storage.session会在扩展重新加载、更新或浏览器重启时清空，不能保证从0.2.15常规重载升级时迁移，已丢失的调整无法恢复；当前没有JSON自动导入功能。[浏览器官方存储说明](https://developer.chrome.com/docs/extensions/reference/api/storage#storage-areas)
- 关闭再打开侧栏会保留当前分析；更换参考图/上传会清空当前商品列表，但长期分类记忆独立保留。无需启动本机模型来保存记忆。保存失败会恢复原分类并明确提示，不会假装已记住。多窗口共享同一浏览器本地记忆并同步显示；写入由扩展worker排队处理，不用过期侧栏缓存覆盖其他决定。
- 记忆仅在同一浏览器用户资料内生效，不上传云端或训练模型；换电脑、换浏览器/用户资料不会自动同步。卸载扩展或清除本扩展数据会删除记忆，留档可导出JSON（当前没有自动导入备份功能）。长期记录只存参考标识/摘要、候选来源/ID、决定和时间，不存图片、价格或标题。
- 导出保留manualReferenceKey、自动status、manualClassification（用户决定/时间、persistent与referenceKey）和effectiveStatus最终分类；人工同款的词来源标为manual-match，人工排除不参与Top10/关键词。匹配策略仍为title-groups-outline-v16。自动核对仍会自行运行，人工操作是可选纠错，不是每条结果的必填确认。

## 价格与标题

- 同款卡片优先展示页面原标题摘要、价格和商品链接；“商品详情”保留完整原标题、复制按钮、来源与采集时间，不让模型改写商品名称或生成价格。
- 读取可见当前价格时排除划线原价和优惠券金额；无法可靠读取时显示未知。价格区间、起价与预估 / 优惠价分别标注，具体 SKU / 优惠条件未绑定时不会宣称是结算价。
- 使用已抓取页面的原始标题和价格，保留来源 / 采集时间；核对时不补开详情页。兼容重复的货币符号（如 $ $1.68）、拆分的货币符号 / 整数 / 小数、纯数字价格容器与价格区间，并持续同步后加载的价格；价格更新独立于图片核对，主体核对期间也持续同步已有商品的价格，并允许点击读取按钮更新价格，不改变正在核对的图片或文字。缺少价格或规格时保留未知。价格升降序按普通显示价 / 区间起点 / 起价排列，同一明确币种或原页面货币符号分别成组，不补造币种或换算汇率；未知价格和优惠预估价放最后。
- 默认优先展示页面同图匹配，再展示后续主体核对结果；可切换价格从低到高 / 从高到低，或按同口径销量排序。标题保留页面全文（上限 2,000 字符），外观层级及未核实规格随结果显示。

TEMU 图片地址可能以 `.jpg` 结尾，但通过 `format/avif` 返回 AVIF 内容。站内图片现在按实际内容解码，并自动转换为 PNG 后识别，支持 JPEG、PNG、WebP、AVIF 和 GIF 首帧。图片体积 / 像素限制仍保留；返回网页、文本或损坏内容的地址会明确提示重新选择产品图片。

## 销量与关键词

- 只读取商品页面明示的已售文字，不把评价数、评分、库存或“热卖”当作销量。
- `10K+ sold` 保留为下限；`4.2K sold` 保留为约数。未知销量不会伪造为 0。
- 只在已自动匹配结果中排序，来源中的“外观同款”层级明确保留；不同国家站或不同统计周期分别处理。统计周期未知会明确注明。
- “销量最高”只限已采集且工具自动确认同款的结果。默认每批核对12个商品，后续已读候选自动进入下一批；可设置每批1–40个。0.2.18每次分析最多保留50条候选，先采集再主体核对；每批数和销量Top10分别控制核对节奏与展示数量。手动检索最多选3组真实原词，共用50条上限，已创建的结果页保留。仍无2分钟总时长截断，不把搜索页读完当作穷尽全站同类商品。
- 销量Top10先筛选主体一致、主体颜色补充或主体轮廓补充同款中有销量的商品，再在同一国家、数据来源和统计周期内按页面显示数字取前10款。不足10款按实际数量展示；无关键词的商品仍保留名次，未知销量不入榜，明确0销量可参与排序。约数和销量下限保留原标识，无法证明精确名次；相同数字保持采集顺序。
- 优先收集商品行、商品卡片或对应商品结构化信息中明确标注的关键词，要求商品 ID 对应、词出现在原文证据内且有采集页面，保留原词、证据、来源链接与采集时间。未关联具体商品的图搜推荐词不进入推荐。没有有效关键词字段时，按标点摘录最多 3 段商品标题原词，不翻译、不组合、不让模型补词，侧栏标注“商品标题原词”。标题缺失或无法摘录时保留空结果。重复同步不累积重复词，也不保留本次页面已移除的旧词。
- 每款卡片在商品图片旁直接显示本链接的销量及前三条页面关键词或标题原词，可逐条复制；完整原词、原文证据和采集来源在卡片内展开。同款、未确定及非同款分类都能查看各自原词，未确定/非同款词不进入同款推荐，未知销量保持未知。
- 底部“销量Top10汇总”保留折叠排名，逐链接显示原标题、页面价格、销量、同款依据和关键词；全部商品的逐卡片展示不改变Top10资格或统计口径。
- 分析可导出 JSON，包含销量分组、每组入选前10款商品及salesRank / keywordEvidence、全部候选、每条同款链接的词证据、采集时间、判断依据与规格缺失项。新增collection / collections保留各次查询累计去重数量、结果页、采集状态与停止原因，siteWideComplete恒为false，不能以采集数量推算全站总量。汇总keywords保留兼容；手动检索记录单独导出。
- 第三方数据明确标为“来源：特卖数据图搜”；与 TEMU 页面已售数字分开排序。国家站未知时，相关状态保留在商品详情和销量分组，默认卡片不再显示国家站未核实提示。
- 第三方销量默认读取周期未知的“已售出”数字。设置可改为页面明确展示的日 / 周 / 月 / 累计销量；缺少所选周期时保持未知，不拿其他周期补齐。
- “月销量”和“近 30 天销量”、“周销量”和“近 7 天销量”分别保留，未确认定义一致时不放入同一排名。
- “畅销同款商品关键词”指销量领先商品的页面关键词或标题原词，不代表这些词自身的搜索量、销量贡献或转化率最高。未确认同款或没有页面销量时，不输出推荐词。


## 本机识别与验证范围

主体分割采用固定BiRefNet-lite512 fp32导出962e679，DINOv2-small及CLIPSeg保留原固定版本，在本机ONNX Runtime运行。模型仅从本地加载，特征缓存按原生引擎版本与设备隔离。主体、颜色和轮廓门槛保持原规则；预处理与运行环境变化可能影响输出，不承诺与历史浏览器版逐图一致。

0.4.2清理了停用的浏览器Worker、WASM适配层及构建脚本，以及已被真实标题原词流程取代的图片生成关键词/云识别入口。当前模型及许可证移至native目录，正常构建无需准备旧浏览器资源。历史方案和验证记录保留，旧源码可从Git历史查询；当前识别缓存、原始测试图片和长期人工分类不作为废弃文件删除。

验证范围和实际结果见[VALIDATION.md](VALIDATION.md)。自动化测试及少量图片链路通过不表示真实识别准确率、跨拍摄角度效果或全站覆盖；用户账号下第三方完整查询仍待现场验证。

## 开发与打包

维护者构建需要Node.js22+、pnpm和Python3。模型、运行库和ZIP为生成文件，不提交Git；首次构建从固定官方/模型仓库版本准备资源，后续校验SHA-256复用。不要将用户缓存、图片、认证信息或人工分类记忆放入包中。

```powershell
pnpm install --frozen-lockfile
node --test --test-concurrency=1 tests/*.test.mjs
node scripts/package.mjs
python scripts/verify-package.py
```

package脚本自动准备native/model-lock.json中固定的模型及原生运行环境，校验SHA-256后复用；同步shared规则并生成完整Windows包及轻量扩展包。可单独运行node scripts/prepare-models.mjs准备模型。验证检查逐文件摘要、模型固定SHA-256、源码一致性、稳定扩展ID与CSP。本机请求应绕过代理；外部资源准备可按已有网络配置使用`NODE_USE_ENV_PROXY=1`。

许可证与来源随包置于licenses，源码位于native/licenses，固定模型摘要见native/model-lock.json。源码维护约定见AGENTS.md；结果记录后提交并推送origin/main。当前生产后台启动/自启仍走scripts/service-control.mjs与service-autostart.mjs；不要同时运行多个目录占用43187。
